# M3 constrained agent — implemented, live evaluation pending
The Python/FastAPI stack is retained; no new agent framework or autonomous subagents. Agent POST /api/agent/tasks requires the existing authenticated session. Body:task1–2000 chars,optional invoice_id,allow_proposal boolean(defaultfalse); explicit invoice required if proposal permissiontrue. This never grants a role or banking execution permission.

## Model boundary
Provider-neutral Chat Completions HTTP adapter uses environment-only base URL/model/key. HTTPS/exact host allowlist,no redirects/no environment proxies,20-second total deadline,<=8-second individual HTTP timeout,<=64KiB decoded response,<=24KB request body,600 completion-token request cap,two provider requests/no retries. Configuration must be explicitly supplied. No API/model credential is shipped. Missing/failed service returns503 with deterministic_finance_available:true,not a fake AI result. Twenty attempted tasks/hour/business counts failures too; existing per-session API limits also apply.

First request supplies strict native function schemas. A batch of up to3 planned calls may be returned; backend dispatches sequentially,not concurrently. Whitelist:get_business_snapshot,analyze_invoice,project_cash_flow,compare_financing,propose_payment. Typed arguments forbid extra fields. No approval,execution,SQL,code,role or credential tool exists. A proposed payment must be explicitly enabled by the caller,match the caller's selected invoice,follow analysis of that invoice and be last. Caller role is still checked by backend; a viewer cannot gain propose permission through AI.

Financial services own every amount,fee,source ID,tenant,policy,as_of and permission. Source memo is an untrusted user-message data field,never a system instruction. Raw model prose is not shown. The model's second response chooses a constrained disposition,allowed rationale codes and exact references to all verified facts. Amount/prose/source overrides,invented/omitted facts,omitted risk reasons,privileged tool attempts or unsafe disposition are rejected. Server templates render the rationale,while numbers are displayed from deterministic fact objects and full tool results. This is intentionally constrained explanation selection,not unrestricted financial advice.

Read tools operate in one consistent DB snapshot,then release it before provider network calls. Completion rechecks authenticated identity and runtime dataset fingerprint. Changed balances/source/session context cause409. Actual proposal is deferred until the rationale passes validation; proposal creation + agent result/audit are atomic in M2's locked transaction. No half-validated AI response creates a pending proposal. M2 separately enforces immutable source hashes,payee limits,reserve,independent human approval and posting idempotency.

Runs retain task hash,mode,status,result and signed audit links,not raw user prompts/provider errors/secrets. Mock providers/transports are marked mock_test_only and cannot be selected by an HTTP body or production env toggle. Configured provider is labeled configured_live_provider for calls made through the real transport; configuration alone is not evaluation evidence. Generic DB failure fails closed and can leave a STARTED diagnostic run; it counts against quota and cannot represent a completed proposal/posting. Local admin recovery is not an automatic retry.
