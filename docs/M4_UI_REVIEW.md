# M4 connected financial workflow
Implementation uses React/TypeScript and existing FastAPI contracts; no backend permission/ledger policy was weakened. Eight server-connected views support input validation, loading, empty, error, success, evidence and independent confirmation states. Actual API values drive displayed balances/costs/forecasts. Frontend arithmetic only formats minor units, converts user scenario input to minor units and lays out an illustrative chart; it never authorizes an action.

Session tokens are password input, memory-only, cleared on sign-out/reload. Workspace is keyed by token and requests are aborted on unmount. Server401 ends the session. No localStorage/sessionStorage, public client secret or frontend role-switch capability. Raw invoice memos render as escaped untrusted text; no HTML insertion. No model explanation is invented when AI is unavailable. Action controls disable during requests; backend idempotency remains authoritative. Errors after a timed-out action ask users to refresh before retrying.

Invoice proposal creation leaves ledger unchanged. Independent approver sees payee, amount, source ID, hash, fingerprint and current server balance; must check explicit review confirmation before approve/reject. Server recalculates impact, reserve, payee allowlist, freshness and permissions atomically. Proposal creation response also shows full policy preview. Approver cannot override amounts or hashes. Approval dialog reports server errors within the modal. Native modal handles Escape/focus; form labels, table headings, keyboard focus styling, live status/error regions and within-container table scrolling supplied. Mobile forecast cards stack to prevent broken amount wrapping.

Verification uses a real browser through Vite proxy into FastAPI/SQLite, synthetic credentials generated privately and deleted after runs. It verifies invalid login, no persistent token storage, baseline/what-if amounts, three ranked fictional offers/affordability, AI503 fallback, duplicate denial, owner/viewer/approver separation, confirmation checkbox, Escape/focus return, actual approval/posting/balance reconciliation, signed audit export, all eight views at360/390/768/1366px, session clearing on reload, duplicate-key JSON denial and empty-business valid import. Separate HTTP regression proves concurrent retries, restart persistence and offline audit verification. No live LLM, public deployment, independent security audit or full WCAG conformance is claimed. M5 still needs broader adversarial/browser/accessibility/dependency checks and live-provider evaluation.
